# 产品决策记录（ADR-lite）

> **这是什么**：用户已经做过的**产品方向决定**，以及为什么这样选。
> `AGENTS.md` 是**约束**（怎么写代码），这里是**理由**（为什么这样选）。
> 冲突时以本文件的产品决定为准——因为它记录的是用户的原话与日期。
>
> **用法**：准备提议一个「改进」「小跟进」或「发现的问题」之前，先在这里搜一遍。
> 已经决定过的事重新提出，等于浪费用户的时间。**若新证据确实与某个决定矛盾，
> 说一次、带上证据、然后等**——不要反复提。

---

## 非目标：视频缩略图不加角标

**决定（2026-09-11，用户原话）**：「现在右下角本来就有文字标识，为啥还要额外加一个」

理由：页脚链接对这些动态**已经**显示「视频动态」，它就是静态标识；媒体上再叠一个图标
等于**第三次**重复（悬停提示是第二次）。

**不要提议**：播放图标、角标、时长胶囊。

---

## 非目标：RSS 卡片不显示配图

**决定（2026-09-11，用户原话）**：「rss不需要这个」

理由：RSS 卡片是以文字优先的渲染，这是决定而非缺失。
**不在其列**：文章**阅读视图**仍然渲染文章自己的图片——那部分在范围内且工作正常。

**不要提议**：卡片缩略图、图片数量提示、卡片配图开关。
**不要**把「卡片没配图」当作缺陷报告。

---

## 不采用 PR-first 工作流

**决定（2026-09-12，用户原话）**：「这个 pr first 不需要做」

背景：外部审计建议改成 branch → 第二 Agent review → CI → merge，理由是「master 不再当实验台」。
工作流维持 **master-first + 文档承载待办**。

该风险由其他手段覆盖：CI 每次 push/PR 跑完整门禁（typecheck / lint / test:coverage / build / E2E），
且真机 E2E 已验证能拦截真实回归（2026-09-12 那批即抓到 2 处）。

**不要重新提出** PR-first 或其变体。

## 待办不迁 GitHub Issues（已决定）

**决定（2026-09-12，用户原话）**：「pr和issues都不需要啊，个人仓库要这个干啥。」

理由：**这是个人仓库**。PR 与 Issues 是协作设施，在一个没有第二个人提交、没有外部
贡献者的仓库里只是额外的搬运成本——待办从 Markdown 搬到 Issues 不解决任何问题，
只多一个会过期的镜像。

**不要提议**：把待办迁到 Issues（或任何外部 tracker）、为仓库开启 Issues、
用 PR 流程代替直接提交。

**当前事实**：待办入口是 `docs/PROJECT_PROGRESS_2026-09.md` §四.P8，**在那里不变**。
`AGENTS.md` 里**没有**待办（其 `Fix queue` 曾是一份全部 DONE 的债务台账，2026-09-12 已移入
`docs/AGENTS_CASES.md`）。

> 这条与上面的 PR-first 是同一个判断的两半：**个人仓库不引入协作开销**。
> 2026-09-12 审计的 P2-17（a）与 P2-16 由此全部关闭。

## 记录格式

新增条目时保持同样的三段：**决定（日期 + 用户原话）** / **理由** / **不要提议什么**。
用户的原话要逐字保留——它是这个文件唯一的权威来源。
