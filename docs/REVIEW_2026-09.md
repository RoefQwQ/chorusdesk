# Code review — 2026-09

One-off audit of Chorus / creator-feed-hub (~14.6k lines, 95 source files, 10 platform adapters).
Reusable constraints extracted from this review live in `AGENTS.md`; this file is the evidence
register and is not required reading for routine work.

Scope: MV3 compliance, security, functionality, extensibility, structure, code quality.

Provenance: findings marked ✓ were verified by direct file reads during synthesis. Unmarked
findings come from parallel review passes over the adapter layer, data layer, and UI layer and
carry their original `path:line` citations, but were not independently re-read.

## Security

✓ **BLOCKER — credentials gated by substring host match.** `bgFetch.ts:73` used
`url.includes('rplay.live')` before attaching the stored bearer token at `:82`; `:47` did the same
for bilibili cookies. Matches `https://evil.example/?ref=rplay.live` and
`https://rplay.live.attacker.tld/`. `proxyImage.ts:42-47` already did this correctly via
`new URL().hostname` + regex — the two handlers had diverged. → `AGENTS.md` rule 1. Fixed.

✓ **BLOCKER — `BG_FETCH` was an unvalidated, readable authenticated proxy.** `background.ts:23`
discarded `_sender` for all 7 message types. `bgFetch.ts:91-103` took caller-supplied `method`,
`headers`, and `credentials` (defaulting to `'include'` at `http.ts:41`), had no scheme/host check,
and returned the full response body — SSRF with readback over every host permission. Bounded today
only by `externally_connectable` being unset, i.e. by a manifest default rather than by code. Any
dashboard XSS or future content script would have escalated to full read access to the user's
bilibili/x.com sessions. → rules 3, 4. Fixed (GET-only, credential allowlist, router-level sender
policy).

✓ **MAJOR — DNR rules rewrite third-party requests.** `declarativeNetRequest.ts:11-131`: six rules
with no `initiatorDomains` and `resourceTypes` including `sub_frame` (`:26,45,57,81,105,129`). Any
site the user visits that embeds sinaimg / pximg / xhscdn assets has its hotlink protection
silently stripped. Scope overreach and CWS policy exposure. → queue #5.

✓ **MAJOR — backup import is effectively unvalidated.** `parseBackup` (`backupRepository.ts:73-91`)
checks only "is this an array / an object". `version: '1.0'` is written at `:42` and never read on
import despite a "DO NOT CHANGE" contract comment. `restoreBackup` (`:57-63`) `bulkPut`s unvalidated
records. Semantics are upsert-merge, not snapshot-replace, so the UI's "全部恢复" overstates.
`:62` also nests `saveSettings`'s read-modify-write inside the transaction. → queue #7.
Prototype pollution assessed as low risk: `JSON.parse` and object spread both use
define-own-property semantics.

✓ **MINOR — Rplay token posture.** Plaintext in `chrome.storage.local` (unencrypted, readable by any
extension page), written from three paths (`rplay-sync.content.ts:14-16`, `background.ts:76-77`,
`rplaySync.ts:79-80`), never cleared on logout. Prefer `storage.session` + expiry.

### Verified clean

✓ No injection surface: zero `v-html`, `eval`, `new Function`, or remote code anywhere. The single
`innerHTML` (`rss.ts:63`) targets a detached div and only reads `textContent` — not exploitable,
though the same file already has a DOMParser.
✓ No path traversal: `pathResolver.ts:7,14-19` strips illegal characters and leading/trailing dots
(`..` collapses to the fallback); `:77-93` whitelists 6 extensions.
✓ No exfiltration: no telemetry, analytics, or third-party CDN scripts.
✓ Manifest declares no `web_accessible_resources`, no relaxed CSP, no `<all_urls>`.
✓ Content script correctly isolated; page JS cannot reach `chrome.*`.

## MV3 compliance

Correct: ✓ listeners registered synchronously at top level (`background.ts:9-23`); no mutable SW
module state; ✓ every async handler returns `true` and calls `sendResponse` exactly once
(`bgFetch.ts`, `proxyImage.ts:36-138`, `twitterTimeline.ts:34-53`); ✓ `chrome.alarms` not
`setInterval`; ✓ DNR instead of blocking webRequest, `removeRuleIds` before `addRules`
(`declarativeNetRequest.ts:134-137`); ✓ 18 enumerated `host_permissions`, no `<all_urls>`;
`activeTab` for popup detection; default CSP intact.

✓ **MAJOR — alarm countdown reset on every SW start.** `setupAutoSync()` runs unconditionally at
top level (`background.ts:10-11`) and calls `alarms.create(..., {periodInMinutes: 30})`
(`autoSync.ts:14-15`). Same-name `create` replaces the alarm, so any popup/dashboard interaction
within 30 minutes means auto-sync never fires. → queue #4.

✓ **MAJOR — background auto-sync cannot fetch at all.** `autoSync.ts:33` runs adapters inside the
SW, but every adapter fetch goes through `http.ts:34` `sendMessage({type:'BG_FETCH'})` (and
`twitter.ts:18` likewise). `runtime.sendMessage` is not delivered to listeners in the sending
context, so `lastError` fires, `http.ts:47` resolves `null`, and `http.ts:66` returns
`扩展后台请求不可用`. Fixing only the alarm would ship a feature that still does nothing.
→ rule 6, queue #4.

✓ **MAJOR — Chrome-only.** All raw `chrome.*`; `wxt/browser` never imported. Firefox MV3 DNR lacks
`modifyHeaders`, which is the entire mechanism behind image hotlink bypass — images would break with
no fallback. Either add a strategy layer or document Chrome-only.

✓ **MAJOR (store policy) — x.com private API scraping.** Hardcoded guest bearer
(`twitterTimeline.ts:21-22`), private GraphQL operation IDs (`:143,169,314`), user `auth_token`/`ct0`
from `chrome.cookies` (`:58-61`). ToS-violating, fragile, and an increasingly common CWS rejection
trigger. Combined with Referer/Origin spoofing this needs an explicit justification story.

✓ **MINOR — `tabs` permission looks droppable.** Every `chrome.tabs` use is either permission-free
(`create`/`remove`/`query`) or reads `tab.url` on hosts already covered by `host_permissions`
(`background.ts:68`, `rplaySync.ts:48-51`, `twitterTimeline.ts:199-201`); popup reads are covered by
`activeTab`. It mainly buys the "read your browsing history" install warning. Also prefer
`declarativeNetRequestWithHostAccess`.

✓ **MINOR — RSS vs. closed host list.** `rss.ts:11` accepts arbitrary feed URLs but
`host_permissions` is a fixed 18-host list, so self-hosted feeds silently fail. Needs
`optional_host_permissions`. (Note the interaction with rule 3: credentials and reachability are
separate concerns.)

✓ **MINOR** — no `default_locale`/i18n, no `minimum_chrome_version`, production `console.log`
(`background.ts:10,76`), fire-and-forget async at top level.

## Functionality bugs

✓ **Unread badge and bookmark count permanently 0.** `database.ts:16` indexes `isRead`/`isBookmarked`;
adapters write booleans (`bilibili.ts:158` and 9 more); queries use numbers — `equals(0)`
(`autoSync.ts:45`), `equals(1 as any)` (`statsService.ts:10`). Booleans are not valid IndexedDB
keys, so the records never enter the index. Double fault; the `as any` was the tell. → rule 5,
queue #3.

**NaN timestamps hide posts permanently.** `rss.ts:96` yields `NaN` for unparseable dates; the
watermark filter `p.publishedAt > sinceTimestamp` (`channelSync.ts:143`) is then always false. Same
pattern in youtube / fantia / rplay. → queue #6.

**`Math.random()` ID fallbacks defeat dedup.** `bilibili.ts:96-98`, `youtube.ts:76`, `rss.ts:52-54`.
Upserts key on `post.id`, so each sync inserts a new row and tombstones/restore break. → queue #6.

**`btoa(guid)` throws on non-ASCII** (`rss.ts:99`), failing entire Chinese/RSSHub feeds. → queue #6.

**Failures reported as success.** Several adapters catch, `console.warn`, and return an empty result
with no `error`; the caller then sets `status:'success'` and `lastSuccessAt`. Deep-dig treats
`rawFetched === 0` as end-of-history (`historySync.ts:117`), so a transient network failure silently
ends the dig. → queue #8.

✓ **Unknown platform silently becomes RSS.** `getAdapter` returns
`ADAPTER_MAP[platform] || ADAPTER_MAP['rss']` (`registry.ts:28`), making the "不支持的平台" branch at
`channelSync.ts:43-45` dead code. → queue #8.

**Fabricated pixiv timestamps.** `pixiv.ts:69-72` linearly interpolates publish time from artwork ID
— directly conflicts with watermark-based incremental sync.

**No retry or backoff anywhere**; only hardcoded sleeps. `requestDelayMs` is consumed solely by the
dashboard's manual batch path, never by adapters or sync.

## Structure and quality

Strengths: ✓ layering boundaries largely hold (repositories never import `chrome.*`; adapters never
import the db); composables genuinely own state, views receive typed context objects and emit
intents; props/emits fully typed; listeners consistently cleaned up on unmount; real transactions
where they matter (`creatorRepository.ts:26-34`, `backupRepository.ts:57-63`); ✓ the
`PlatformAdapter` contract (`adapters/types.ts:29-59`) means a new adapter inherits watermark
incremental sync, cursor paging, tombstone filtering, timeouts, and pacing for free.

Debt:

- **`CreatorsView.vue` is 1420 lines** with ~5 responsibilities and three near-duplicate render
  modes (grid 690-929, list 931-1174, detailed 1176-1418).
- ✓ **`application/` facade is half-adopted.** Methods are 1:1 forwards (`postService.ts:18-19`,
  `creatorService.ts:17-18`) while 5 composables and the whole popup import `infrastructure/db`
  directly (`useDashboardShell.ts:3-9`, `useQuickFollow.ts:4-5`). Two legal paths to the same
  persistence is the worst intermediate state. → queue #10.
- **Duplicated logic with split state.** Avatar-failure fallback exists in both
  `useCreatorsManager.ts:43-88` and `CreatorsView.vue:148-166` with *separate* `failedAvatarUrls`
  refs, so the same broken avatar behaves differently per surface; `getRoleLabel`, relative-time
  formatting, and waterfall height estimation are each duplicated; the Post literal is rebuilt 13
  times across 10 adapters.
- ✓ **Indexes built and then bypassed.** The watermark query uses `.reverse().sortBy('publishedAt')`
  (`channelSync.ts:79-83`), loading every post of a channel into memory, though v2 added
  `[channelId+publishedAt]` for exactly this; tombstone filtering pulls all recycle-bin keys每 sync
  (`:149`) while `channelId` is indexed; the same file uses `primaryKeys()` at 130 but `toArray()` at
  182. → queue #9.
- **Accessibility gaps.** Six modals are plain fixed divs with no `role="dialog"`, `aria-modal`,
  focus trap, or scroll lock; Escape works only for the lightbox (`App.vue:259-262`); many icon-only
  buttons carry `title` but no accessible name. → queue #11.
- ✓ **Dead code.** `src/db/index.ts` (zero importers), `DashboardSection.vue` (4-line shell,
  acknowledged at `docs/ARCHITECTURE.md:420`), `platformAuthService` (never called). ~60 `any`.
- ✓ **Zero tests, lint, and CI** — `package.json` has only `dev`/`build`/`zip`. Also
  `typescript: "^7.0.2"` is a caret range on an unstable compiler major with no CI typecheck; pin it.
- Leftover artifacts: `.e2e-chrome.log`, `HANDOFF_AVATAR.md`.

## Extensibility: adding one platform

The adapter contract is the easy, well-factored part. The cost is peripheral — 6-8 edits, none
type-checked as a set: adapter file → `registry.ts:14-25` → `PLATFORM_REGISTRY`
(`types/index.ts:28-149`) → `urlParser.ts` host branch → `hosts.ts` + `wxt.config.ts`
host_permissions → DNR rule if the CDN is hotlink-protected → `proxyImage` allowlist/referer map →
**two duplicated cookie-auth tables** (`platformAuth.ts:29-38` and `usePlatformLogins.ts:11-20`,
with a third cookie-name set inside adapters). Domain knowledge lives in five places with no single
domain→platform→adapter→auth map.
